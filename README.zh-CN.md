# Open Research (`open-research`)

[English](./README.md) | 简体中文

**一个专门教 AI「怎么全网深度搜索、怎么交叉验证、怎么把杂乱信息整理成清晰结论」的通用 Agent Skill。**

平时让 AI 联网搜索，它往往只是随手搜一两次、把排名前几的网页拼凑一下就回答你。装上 `open-research` 后，你的 AI 助手（Claude Code、Codex、Comate、Cursor 等）会自动按一套严密的调研规范工作：**跨平台中英双语搜索 → 排查反面证据与项目维护状态 → 核验信息时效性 → 过滤洗稿同源信息 → 整理成结论先行、层次分明的结构化报告**。

---

## 这是什么？

`open-research` 是一个**零外部依赖的 AI 搜索与信息整理技能（`SKILL.md`）**。它不局限于 AI 或软件测试，在任何需要「查资料 + 理清脉络」的场景下都能直接触发：

- **写论文与文献综述**：指导 AI 检索中英文学术库、回溯一手引文、排查撤稿与复现失败记录，帮你把「学界共识」和「方法论争议」整理得明明白白。
- **了解行业与政策调研**：指导 AI 横向搜索北美、欧洲、中国/亚洲等多个地区的政策文件、财报与行业数据，整理出跨国对比简报。
- **评估 GitHub 开源项目与工具**：防止 AI 只看 Star 数瞎推荐——强制 AI 去查最新 Release、依赖兼容性、Issue 维护活跃度和开源协议。
- **日常深度搜索与避坑求证**：买东西做功课、查政策细则、对比技术方案或考据某个争议话题时，让 AI 多角度搜索并把各方观点、优缺点和未证实线索整理清楚。

## 为什么 AI 需要专门的「搜索与整理」Skill？

没有规则约束时，AI 默认的联网搜索经常犯四个毛病：
1. **单一语言信息茧房** —— 你用中文问，它就只搜中文，漏掉英文原版论文、海外一手文档或本地政策。
2. **只报喜不报忧（证实偏差）** —— 只看排名前几的宣传稿，不主动搜「局限性」「翻车」「撤稿」「停更（archived）」或「破坏性更新（breaking changes）」。
3. **被洗稿内容糊弄** —— 看到五篇公众号/博客转述同一篇通稿，就以为找到了「五个独立来源」。
4. **没有时间观念** —— 把两年前已经作废的 API 文档、早就不维护的高 Star 仓库、或已被推翻的旧研究当成现在的事实喂给你。

`open-research` 把 **`open-research`（多平台广度搜索）**、**`github-industry-research`（GitHub 与行业深度调研）** 和 **`source-freshness`（信息时效审计）** 三套能力融合成一个独立文件，手把手规范 AI 的搜索动作与整理格式。

## 它如何指导 AI 搜索与整理？

### 1. 自动匹配三档搜索深度
AI 在开篇会先用一句话告诉你本次使用哪一档：
- **`Quick`（快速档）**：3–5 次搜索，覆盖 2+ 类来源。适合日常「简单查一下」「大概说说」。
- **`Standard`（标准档，默认）**：8–15 次搜索，覆盖 4+ 类来源。强制中英/多语言互搜 + 核心结论交叉验证。
- **`Deep`（深度档）**：覆盖 6+ 类来源，自动拆分子问题（支持派多个子 Agent 并行搜索），并对长文结论做逐句事实核查，适合「深入调研」「写报告」「写综述」。

### 2. 四维换问法搜索（打破信息茧房）
同一个问题，AI 不会只搜一次，而是从四个维度扩展：
- **中英/多语言互搜**：中文搜一轮 + 英文地道专业术语搜一轮（拒绝生硬逐字直译）。
- **同义词与行业黑话**：日常叫法 + 学术/法律/行业正式术语搭配搜。
- **多视角切换**：分别按「定义原理」「实操怎么做」「真实案例」「定量数据」四个角度搜。
- **强制搜反面（对抗性检索）**：专门搜 `问题 / 局限 / 批评 / 撤稿 / 停更 / 争议`（`limitations / criticism / retractions / archived / vs`）。

### 3. 内置时效性体检（拒绝过时信息）
AI 会把每条信息的**事件发生日**、**发布/更新日**和**今天访问日**分开记录，并打上四级时效标签：
- `[Current]`（当前有效）
- `[Aging]`（临近过时窗口，引用需注意日期）
- `[Stale]`（已过时或已被新版本/新政策取代）
- `[Unknown]`（找不到日期或兼容性未验证）

### 4. 把搜索结果整理成高可读性报告
AI 不会丢给你一堆乱七八糟的链接，而是按固定结构整理好：
- **结论先行（`截至 YYYY-MM-DD`）**：第一段先给能直接用的结论，细节放后面。
- **事实与观点严格分家**：每条要点明确标注 `[Fact]`（一手事实）、`[Interpretation]`（综合解读）或 `[Recommendation]`（建议）；单一来源标 `[Single Source]`，厂商软文标 `[Vendor/Commercial Interest]`。
- **争议、盲区与未证实线索透明化**：各方说法冲突时并列展示；没查到的地区或平台（如社媒仅部分收录）主动说明；找不到一手出处的传闻单独放进**未证实线索**。
- **清爽易读的排版**：默认跟随你的提问语言输出（外文资料附原标题 + 链接），短句短段落，单张表格最多 4–5 行，扫一眼就能抓住重点。

## 工作流概览

```text
你的提问
   │
   ▼
1. AI 选定搜索档位 (Quick / Standard / Deep)
   │
   ▼
2. AI 跨平台多语言搜索 (8 大类来源 + 跨地区覆盖)
   │
   ├──► 反面检索 (局限 / 批评 / 撤稿 / 破坏性更新)
   └──► GitHub 专项体检 (Releases / 依赖兼容性 / 维护状态 / 开源协议)
   │
   ▼
3. AI 核验时效性 (事件日 vs. 更新日 vs. 访问日 → Current / Aging / Stale / Unknown)
   │
   ▼
4. AI 交叉验证与去重 (回溯一手出处 + 区分 事实 / 解读 / 建议)
   │
   ▼
5. AI 整理输出结构化报告 (截至 YYYY-MM-DD 结论 + 核心要点 + 盲区说明 + 来源清单)
```

## 安装方式

`open-research` 采用标准 `SKILL.md` 格式编写，**没有任何外部依赖**，复制单个文件即可使用：

```bash
# Codex 个人技能目录
mkdir -p ~/.codex/skills/open-research
cp SKILL.md ~/.codex/skills/open-research/SKILL.md

# Comate 个人技能目录
mkdir -p ~/.comate/skills/open-research
cp SKILL.md ~/.comate/skills/open-research/SKILL.md

# Claude Code 个人技能目录
mkdir -p ~/.claude/skills/open-research
cp SKILL.md ~/.claude/skills/open-research/SKILL.md
```

*(Windows 用户直接将 `SKILL.md` 复制到 `$HOME\.codex\skills\open-research\` 或 `$HOME\.comate\skills\open-research\` 即可。)*

## 你可以这样问 AI

- **写论文 / 查文献**：
  > “我正在写一篇关于『微塑料对人体心血管系统影响』的综述论文，帮我搜索并整理一下 2024–2026 年最核心的临床研究进展、学界共识以及方法学上的主要争议。”
- **了解行业 / 跨国政策对比**：
  > “帮我查一下目前美国、欧盟、中国、日本对『钠离子电池储能商业化』的政策支持、头部企业量产进度和成本瓶颈，整理成对比简报。”
- **GitHub 开源选型 / 日常折腾**：
  > “我想把家里几万张老照片做本地自托管管理（支持人脸识别、不上传云端），帮我全网搜索并整理目前最活跃的 GitHub 开源方案对比，看看近期维护状态、避坑点和硬件门槛。”
- **日常快速求证**：
  > “简单查一下：现在欧洲旅客来中国的过境免签时长是多少小时？政策最近一次更新是什么时候？”
